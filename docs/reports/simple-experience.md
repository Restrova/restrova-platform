# Four-section restaurant experience

The primary desktop and mobile navigation has exactly Home, AI, Data and Settings. Existing financial, forecasting, alerts, menu, import and administrative routes remain available through contextual links. Notifications open the authorized alert center; a single branch is displayed without an unnecessary selector.

Home uses an authorized current-day snapshot in the restaurant timezone, three metrics, a single seven-completed-day revenue chart and one next action. Missing costs never turn into zero costs or asserted profit. Negative chart values use warning color with their signed amounts. An empty owner account gets connect/upload onboarding, with an explicit skip action.

AI defaults to the header's selected branch. Today questions use a stored, digest-bearing snapshot of actual records and explicit partial-day language. Other established tools retain their completed-period scope. The assistant remains evidence-based and deterministic when no external model is configured. Arabic today answers use professional Saudi phrasing.

Data shows source availability and last-record timestamps. Mapping and validation remain in the existing import wizard; automatic mappings are retained. Successful sales imports summarize only newly inserted lines: net sales, distinct branch/order pairs, source date range and highest-quantity dish. These are not all-time restaurant totals. Duplicates do not contribute to the reward summary. The import's scoped audit event retains this summary. Aggregated report uploads retain their separate full-period analysis path.

Manual entry is an optional, branch-scoped current-day summary for owners and branch managers. Total costs include waste. Currency precision is checked exactly. A second summary or an entry overlapping current imported/ledger data is refused. Subsequent imported/ledger transactions supersede the manual snapshot; the two are never summed. Manual summaries feed Home and today's AI answer, not item economics, forecasts or ledger reports, because they lack transaction and item detail. Migration 0013 is additive. Manual corrections/edit history are not introduced here.

Settings groups restaurant details, branch/team/integration links, actual language preferences and account details. Tabs follow role permissions. Provider connections show existing real availability: this change does not enable an unconfigured POS provider or promise automatic sync. Provider-specific credentials and implementations remain separate work.

Two illustrations derived from the supplied Restrova reference are used only on login and the first-run welcome. The application dashboard has no decorative food photographs or embedded mockup figures. All displayed operating figures come from scoped API data.

Validation includes role/tenant boundaries, exact money, duplicates, imported/manual precedence, saved AI evidence, locale direction, four-item navigation and import-driven refresh. Authenticated visual review requires an authenticated browser session; automated component and API tests do not replace that review.
